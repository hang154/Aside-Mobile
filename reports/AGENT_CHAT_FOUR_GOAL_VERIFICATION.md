## 실행 책임과 범위

호스트의 사용자 서비스 `nubi-goal-chat.service`가 앱 메시지를 받아 기존 Azrael Qwen 연결로 실행기를 자동 시작한다. 아즈라엘에서 매번 CLI 명령을 입력할 필요가 없다. Qwen의 tool_calls를 MCP에 전달하고, 실제 기기 결과를 Qwen에 돌려줘 다음 행동을 고르게 한다. 아즈라엘 주 대화 모델을 교체하거나 아즈라엘 대화 세션에 앱 요청을 자동 등록한 것은 아니다. 태블릿 내 27B 추론도 아니다.

앱에서 선택한 정확한 목표 ID와 캐릭터를 작업에 고정한다. 네 에이전트는 같은 형식과 실행기를 쓰면서 대화·초안·검색 주제·출처를 목표별로 분리한다. 후속 요청에는 같은 목표의 최근 대화 일부를 전달한다. 첫 검색이나 첫 도구는 강제하지 않고 허용된 공개 탐색 도구 안에서 Qwen이 선택한다.

## 검증과 수정

- 실기기 DB·소유권·구매 예외·채팅 분리·초안/중지 검사 45개. 같은 캐릭터의 다른 목표 열기 거부, 목표별 대화 저장과 재열기를 포함한다.
- Java 규칙 143개, 고정 DOM 추출기 fixture 30개, 정적 검사 3종. GitHub Android 빌드/자동 검사 통과.
- 호스트 모의 작업 검사 12개, MCP 경계 검사 15개, 모의 실행기 통합 3건. 이 결과를 실제 Qwen 실행 성공과 혼동하지 않는다.
- 실제 HTTP 인증/입력/작업 경계와 세션별 대기열 분리를 확인했다. 이전 폴링과 새 폴링을 동시에 열어 다른 세션의 명령을 가져가지 못하는 것을 검사했다.
- 실제 중지 버튼으로 호스트 Qwen/MCP 프로세스 취소를 확인했다. 화면 이동 시 폴링을 중단하고 늦은 submit/status 응답을 다음 대화에 표시하지 않는다.
- 최초 `error:null`의 실패 오인, 이전 화면 폴링의 명령 가로채기 가능성, 네이버 날짜 링크가 글 제목을 선점하던 문제, API 실패가 중지로 표시되던 문제를 수정했다. 날짜·프로필·중복 본문 링크 제외 fixture와 실제 네이버 DOM으로 제목 추출을 확인했다.
- Android Keystore AES-GCM 페어링 저장 후 앱 프로세스를 다시 시작한 각 시나리오에서 수동 재입력 없이 복원했다. 인증키/모델 bearer는 채팅·Git·캡처에 넣지 않았다.

모델 API의 시간 초과와 SSL EOF로 중간 실행이 실패했다. 시간 초과·일시 HTTP 오류·연결 끊김은 한 번만 재시도한다. API가 복구된 뒤의 최종 네 성공 기록을 판정에 사용한다. 설치 갱신과 겹쳐 종료된 테스트, 직접 수행한 MCP 어댑터 검사, 실패 시도는 성공 근거에서 제외한다.

## 산출물과 남은 한계

로컬 `nubi-agent-chat-0.2.3/`에 최종 APK, 네 목표의 PNG/MP4, 각 instrumentation 로그, `four-agent-verification.json`, `final-inputs.json`, `jobs/` 전체 추적을 보관했다. 캡처·영상·전체 사용자 대화 추적·인증키는 Git에 올리지 않는다. 비공개 테스트 배포에는 APK·체크섬·설명만 포함한다.

현재 범위는 허용된 공개 사이트의 검색, 제목·메타데이터 관측, 선택한 원문 열기, 출처와 요약 저장이다. 주문·결제·예약·가입·메시지 전송·실시간 매칭·영상 내용 분석은 수행하지 않는다. 집 사기 결과는 블로그 공개 검색이며 공식 자격 심사나 검증된 매물 조회가 아니다. 모델이 검색어에 과거 연도를 넣을 수 있어 최신성·공식성 자동 검증은 보장하지 않는다.

호스트와 모델 서버가 실행 중이고 태블릿에서 호스트에 접근할 수 있어야 한다. 화면을 벗어나거나 앱을 종료하면 작업을 중지하며 백그라운드 지속 실행은 없다. 현재 작업 상태는 호스트 메모리에 있고 서비스 재시작 후 자동 재개하지 않는다. 네트워크 주소·인증서가 바뀌면 다시 페어링한다. 사용자 서비스는 계속 실행하도록 유지하고 임시 USB 화면 유지 설정과 개발용 포워딩·녹화는 정리한다.
