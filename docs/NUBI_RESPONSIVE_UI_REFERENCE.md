# 누비 UI 실측 및 반응형 구현

2026-11-01, 연결된 Lenovo TB375FC(물리 1840×2944, 340dpi)의 설치된 Pickle 앱을 실행해 관찰했다. 앱의 소스나 리소스를 추출하지 않고 실제 렌더링 화면·이동·UI 계층을 비교했다. 참고 캡처 및 XML은 로컬 `nubi-responsive-reference`에만 보관한다.

## 실측한 표현

- 태블릿 가로 2944×1840과 세로 1840×2944 모두 약 300dp 너비의 왼쪽 탐색 영역이 유지된다. 기존 누비의 화면 너비 21.6% 계산은 세로에서 크게 달라졌다.
- 1080×1920/340dpi(약 508dp)에서는 탐색 영역이 사라지고 화면 하단에 네 개의 아이콘이 나타난다. 하단을 둘러싼 캡슐이나 메뉴 글자는 없다.
- 배경은 #FFFFFF. 채팅 말풍선의 주요 색은 #F4F4F4, 입력창은 #EAEAEA, 탐색 메뉴 선택 배경은 #F2F2F2이다. 색은 캡처의 실제 픽셀 빈도와 위치에서 확인했다.
- 상단은 원형 메뉴, 가운데 캐릭터와 이름 버튼, 오른쪽 둥근 동작 버튼이다. 입력창은 회색 캡슐, 왼쪽 추가 아이콘, 오른쪽 검정 원형 동작 버튼이다.
- 기본 채팅은 작은 상하 간격으로 말풍선과 링크 카드를 쌓는다. 둘러보기는 흰 바탕의 구분선 목록이며, 보관함은 상단 세그먼트와 중앙의 빈 상태로 구성된다.

## 적용

`NubiCompanionUi`가 동일한 구성 원리를 사용한다. 누비의 캐릭터와 목적 선택, 실제로 제공하는 기능은 누비의 것으로 유지한다. 동작하지 않는 전화 버튼이나 가짜 이용자 수는 추가하지 않는다.

840dp 이상에서 300dp 사이드바, 그 아래에서 아이콘형 하단 탐색을 사용한다. 좁은 화면의 메뉴 버튼은 왼쪽 드로어를 연다. 브레이크포인트는 두 실측 상태 사이의 누비 구현값이며 Pickle의 정확한 내부 상수라고 주장하지 않는다.

`GoalAgentActivity`는 화면 회전·창 크기 변경 시 재생성하지 않고 같은 WebView·대화·입력창을 유지한다. 실제 창 너비에 따라 탐색 영역, 하단 탐색, 말풍선 최대 너비를 다시 계산한다. 시스템 상하 inset은 바깥 프레임에서 한 번 처리하며 키보드에서는 입력창 영역이 줄어든 창에 맞춰 올라온다.

## 검증 범위

전용 네이티브 계측이 임시 목표에서 360dp 휴대폰, 약 508dp 화면, 태블릿 세로·가로를 실제 디스플레이 크기와 회전 설정으로 검증한다. 각 크기에서 사이드바/하단 탐색 전환, 입력창·말풍선 경계, 초안 유지, 둘러보기·보관함 전환과 화면 캡처를 확인한다. 완료·실패와 관계없이 디스플레이 설정을 복구하고 임시 목표를 삭제한다.

완전한 픽셀 동일성이나 모든 Pickle 서비스의 동작 동일성을 뜻하지 않는다. 연결 기능과 캐릭터, 콘텐츠가 달라지는 부분은 누비 UI로 표시한다.
