# Aside Mobile — 제품 목표와 구현 기준

## 목표

10~20대의 취향과 계획에 맞춰 기회를 찾고, 외출·쇼핑·모임·지원 준비를 실제 휴대기기에서 이어 주는 생활 에이전트. 사용자는 관심사와 연결할 앱을 고르고, 찾은 근거와 수행할 행동을 확인한 뒤 실제 행동으로 이어간다. 말투는 친구형·차분한 비서형·실무형을 선택할 수 있는 방향으로 기획한다.

## 공통 사용자 여정

관심사 선택 → 기기에서 사용할 앱 선택 → 직접 요청 또는 등록된 조건으로 기회 탐색 → 근거와 함께 후보 확인 → 계획에 저장·비교 → 사용자가 선택한 앱에서 실행 → 결과 확인. 로컬 모델은 짧은 명령 해석과 초안에 쓰고, 외부 자료는 출처와 조회 시각을 확인한다. 모델 출력이나 화면의 내용은 사실과 성공 여부를 검증하기 전까지 제안으로 취급한다.

## 생활별 목표

1. **공연·팬덤:** 공연·티켓 공지, 출발지와 종료 시각, 막차·귀가 가능성, 숙소 가격과 이동을 함께 비교하고 예매 화면으로 연결한다.
2. **친구 모임·총무:** 날짜와 인원, 장소 후보, 총예산·1인 분담을 정하고 초대·정산을 준비한다.
3. **데이트·맛집·옷:** 예산과 동행 상황을 바탕으로 장소·메뉴·옷·이동 순서를 구성한다.
4. **축제·여행:** 일정과 날씨, 부스·음식, 예약 방법, 대기시간과 이동을 고려한다. 김천 김밥 축제는 예시이며 실제 행사 정보·예약 여부는 당해 공식 안내를 확인한다.
5. **인스타그램에서 발견:** 사용자가 공유하거나 명시적으로 선택한 게시물의 텍스트·링크·이미지에서 관심 내용을 추출하고 관련 음식·상품·장소를 찾는다. 댓글·DM으로만 받는 정보는 실제 접근 가능한 근거가 있을 때만 제공한다.
6. **뷰티·의료기관 탐색:** 사용자 관심사에 맞는 제품과 지역 장소 정보를 출처·시점과 함께 제공한다. 진료 적합성은 개별 확인이 필요하다.
7. **패션·체험단:** 필요한 일정과 예산, 옷장 정보, 모집 기간·조건을 대조하고 사용자 선택 후 신청 화면으로 연결한다.
8. **야구·공연 원정:** 경기·공연 일정과 예매처, 교통, 숙소와 준비물을 연결한다.
9. **대학생활·취업:** MT·축제·장학금·인턴·대외활동의 조건과 마감, 준비물을 정리한다.
10. **부업·창업·자취:** 일자리의 보수·자격, 지원사업의 대상·마감, 생활·구매 조건을 비교한다.
11. **동행 실험:** 참여자가 직접 공개 범위와 조건을 정하고 관심 기반으로 동행을 찾는다. 계정·동의·신고·개인정보 처리와 실제 운영이 필요한 별도 기능이다.
12. **관심 앱과 선제 알림:** 앱과 관심 조건을 등록해, 허용된 정보원에서 확인 가능한 변경만 찾아 알려준다. 등록만으로 자동 감시가 작동했다고 표시하지 않는다.

## 현재 구현과 다음 단계

- **기존 실기기 확인:** 로컬 Qwen 답변, 화면 읽기·스크롤, 관심사·공연 계획 저장, 인원별 예산 계산, 검색 화면 열기, 텍스트 공유 접수.
- **이번 작업 우선순위:** 앱 등록 및 실행을 명시적으로 구현하고, 사용자 요청을 로컬 모델이 제안한 검색·앱 열기로 연결하는 흐름을 실기기에서 검증한다. 모호한 제안은 실행하지 않는다. 기존 생활 계획과 연동한다.
- **이후 별도 구현:** 공식 정보원별 검색·가격 비교·날씨·대기, 일정 최적화, 사용자 선택 기반 알림, 다중 사용자 동행·공유, 로그인과 승인 후 사이트별 실제 예약·신청. 앱별 연결은 실제 사용 가능성과 결과 확인이 필요하다.

## 완료 조건

- 기기에서 등록·저장한 관심 앱과 선택이 앱을 닫았다 열어도 유지된다.
- 자연어 제안에는 실제 수행할 행동과 대상이 표시되고 사용자가 실행을 눌러야 한다. 지원하지 않는 형식은 실행되지 않는다.
- 앱 실행, 검색, 사용자 취소·앱 미설치·잘못된 입력을 태블릿에서 확인한다.
- 날짜·가격·빈자리·발송·예약의 성공을 추측하지 않는다. 계정·비밀번호·인증·결제는 사용자가 직접 처리한다.
- 화면 녹화는 로컬 전용이며, 민감한 화면은 공유 저장소에 넣지 않는다.
