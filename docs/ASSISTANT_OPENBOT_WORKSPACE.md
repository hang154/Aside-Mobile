# 누비 작업공간 UI 0.2.5

사용자는 각 목표의 캐릭터에게 채팅으로 지시하고, 같은 화면에서 Qwen의 브라우저·실행 기록·생성 파일을 확인한다. 기존 OpenMuse 참고 화면과 새 작업공간 화면을 상단 메뉴에서 선택한다. 화면 변경은 진행 중 작업을 마치거나 중지한 뒤 가능하다.

## 참고 구현과 범위

- assistant-ui: `ff654d8156680b839774296ef644b57ab1078425`, [thread.aui.tsx](https://github.com/assistant-ui/assistant-ui/blob/ff654d8156680b839774296ef644b57ab1078425/packages/ui/src/components/react/assistant-ui/elements/thread.aui.tsx). 대화, 입력창, 메시지 작업 버튼, 도구 그룹 구성을 참고했다.
- OpenBot: `743649efc3f21d7bf0badbe6af2bcd5daedd97ce`, [app-sidebar.tsx](https://github.com/CopilotKit/OpenBot/blob/743649efc3f21d7bf0badbe6af2bcd5daedd97ce/app/src/components/app-sidebar/app-sidebar.tsx). 에이전트별 대화와 옆에서 작업을 보는 구성을 참고했다.
- 두 프로젝트 LICENSE는 MIT로 확인했다. 이 버전은 기존 Java Android 화면에 독립적으로 구현한 디자인·상호작용 적용본이다. React 라이브러리나 OpenBot 서버, AG-UI 런타임을 탑재한 버전은 아니다. 원본 코드·이미지·아이콘은 복사하지 않았다.

## 실제 조작

1. 목표에서 `에이전트와 채팅 · Qwen 탐색`을 연다.
2. `작업공간 UI ▾`에서 새 화면/기존 화면을 선택한다. 기존 대화·입력 초안·WebView 세션을 유지한다.
3. `☰ 대화`에서 목표별 대화를 선택한다. 같은 캐릭터여도 정확한 목표 ID로 연다. 상단 운동·연애·학점·집 사기 버튼은 해당 캐릭터의 최근 목표를 연다.
4. 추천 질문을 누르면 입력창에만 들어간다. 사용자 전송 전 실행하지 않는다.
5. 채팅 전송 → 기존 HTTPS 중계의 자동 worker → Qwen → MCP → 기기 WebView 순서로 실행한다.
6. 오른쪽 `브라우저`는 실제 탐색 페이지, `실행 기록`은 서버가 반환한 실제 progress 배열을 보여준다. 완료 답변에도 기록을 저장해 다시 열 수 있다. 모델의 비공개 추론이나 토큰 스트리밍을 꾸며 표시하지 않는다.
7. 답변 `복사`는 텍스트 복사, `요청 수정`은 해당 답변 직전 사용자 지시를 입력창으로 가져온다. 자동 재실행하지 않는다.
8. `파일`에는 현재 목표 대화의 문서 결과만 모은다. DOCX/HWPX 다운로드·열기는 기존 목표 소유권·파일 허용목록·SHA256 검증을 사용한다. 실제 업로드 완료 상태와 초안 상태를 구분한다.
9. 진행 중 중지/앱 이동/다른 목표 전환은 기존 취소 경계를 유지한다. 삭제된 목표를 종료 처리하며 대화를 다시 저장하려 할 때 해당 목표를 복구하지 않고 저장을 건너뛴다.

## 지원 경계

생성 파일만 표시하며 임의의 새 파일 첨부·음성·모델 토큰 스트리밍·AG-UI 외부 에이전트 연결·새 결제 승인 실행은 추가하지 않았다. 문서 파이프라인의 실시간 Outlook 갱신 및 SharePoint 실제 업로드에는 여전히 계정 연결과 목적 폴더가 필요하다. 이번 UI 변경은 이전 쇼핑 가격 조건 시나리오의 반복 검색 실패를 수정하지 않는다.

## 검증 입력과 산출물

원본 dirty 파일과 혼합하지 않기 위해 이전 검증 소스의 복제에 이번 변경 파일만 반영해 빌드한다. 앱 ID를 유지하여 태블릿에서 업데이트 설치한다. APK, 실기기 로그, 화면 캡처는 `../nubi-workspace-0.2.5/`에 보관한다. 캡처·영상·메일/문서 원문은 Git에 넣지 않는다.
