# 네 목표의 채팅 → Qwen → 실제 브라우저

목적은 운동·연애·학점·집 사기의 공통 에이전트 화면에서 사용자가 직접 지시하고, Qwen의 실제 탐색 과정과 출처를 같은 화면에서 확인하는 것이다. 아즈라엘에서 매번 명령행 실행을 시작해야 했던 흐름을 앱 전송 버튼에 연결한다.

## 화면

OpenMuse의 [채팅](https://github.com/CopilotKit/OpenMuse/blob/a4944f4c471d3dc93b8bfc060b5da309b5216ab2/apps/mobile/src/chat.tsx), [브라우저 카드](https://github.com/CopilotKit/OpenMuse/blob/a4944f4c471d3dc93b8bfc060b5da309b5216ab2/apps/mobile/src/browser-tool-card.tsx), 공식 데모 화면을 참고했다. 밝은 바탕, 가운데 캐릭터, 파란 사용자 말풍선, 회색 답변, 둥근 고정 입력창의 전송/중지 전환, 출처 카드와 실제 브라우저 패널을 누비의 Android 네이티브 화면으로 구현했다. React Native/CopilotKit 런타임을 이식한 것은 아니다. 참고 프로젝트 MIT 고지는 `references/OPENMUSE_LICENSE`에 보관한다.

작업실의 `에이전트와 채팅 · Qwen 탐색` → 해당 목표 대화 → 메시지 입력 → 전송 → 검색/읽기 진행 표시 → 답변과 실제 선택지 카드 → 출처를 누르면 같은 브라우저에서 원문을 연다. 상단 네 에이전트 버튼으로 전환한다. 전화·주문·결제·신청·메시지 전송 도구는 제공하지 않는다.

## 실행 계약

1. 앱이 인증·인증서 고정 HTTPS의 `/chat-submit`으로 `goal_id`, `character`, `task`, `request_id`를 전송한다.
2. 호스트 `nubi-goal-relay.py --chat-dir ...`가 `nubi-chat-jobs.py`로 작업을 만들고 `qwen-goal-agent.py --goal-id ... --task ...`를 자동 실행한다.
3. Qwen이 허용된 MCP 도구와 공급자·검색어·순서·후보를 선택한다. 첫 검색·첫 도구는 강제하지 않는다. 도구 결과를 받아 다음 행동을 선택한다.
4. MCP 요청은 같은 중계를 통해 태블릿 전경 WebView로 전달된다. 브라우저는 앱에서 고른 정확한 목표 ID와 캐릭터만 허용한다.
5. 앱은 `/chat-status`에서 상태·관측 결과를 읽는다. 요약은 모델 보고와 목표 DB에 저장하고, 대화 내 출처 카드는 보고서에 포함된 실제 관측 URL과 일치하는 후보만 표시한다.

아즈라엘은 이 호스트 실행 환경을 준비·시작한다. 전송 이후에는 호스트 작업기가 자동으로 Qwen을 호출한다. 아즈라엘 주 대화 모델을 교체하거나 아즈라엘 대화 작업으로 앱 요청을 접수하는 기능은 아니다. 태블릿에서 27B 모델을 직접 실행하는 것도 아니다.

## 목표와 실행 수명

- 대화·임시 입력은 소유한 목표 레코드의 `chatMessages`, `chatDraft`로 저장한다. 같은 캐릭터라도 목표 ID가 다르면 섞지 않는다. 대화는 최신 40개, 후속 요청에는 같은 목표의 최근 4개 메시지 요약만 포함한다.
- 실제 브라우저는 하나다. 연결 세션별로 명령 대기열을 분리하고, 채팅 작업의 MCP 명령은 해당 연결 세션에만 전달한다. 이전 화면의 대기 중 폴링이 새 화면의 명령을 가져갈 수 없다. 호스트는 동시 작업을 거부하고, request_id 재전송은 같은 작업으로 돌려준다. 다른 본문으로 같은 ID를 재사용하면 거부한다.
- 중지·화면 이동 시 `/chat-cancel`로 모델 실행기와 MCP 자식 프로세스를 종료하고 대기 명령을 비운다. 기기 폴링도 중단한다. 늦은 submit 응답은 취소하고 다른 턴에 표시하지 않는다.
- 입력 초안은 중지 후 보존한다. 전송 확인 후에는 비운다. 연결 오류를 세 차례 받으면 취소하고 다시 요청할 수 있다.
- 개별 모델 요청 시간 제한, 단계 16회, 작업 최대 15분을 둔다. 작업 상태는 호스트 메모리에 있으며 서비스 재시작으로 실행을 재개하지 않는다. 대화/결과는 기기에 남는다. 앱 종료 뒤 계속 탐색하는 기능은 없다.

## 로컬 운영

최초에 사용자가 페어링 주소·연결키·인증서 지문을 입력한다. 페어링은 Android Keystore AES-GCM으로 암호화해 앱 전용 저장소에 보관한다. `Qwen 연결 → 연결 삭제`로 지울 수 있다. 인증키·모델 bearer는 채팅/저장소/캡처에 넣지 않는다.

이 워크스테이션에는 사용자 서비스 `nubi-goal-chat.service`를 설치한다. runtime은 `~/.local/state/nubi-goal-chat/`이며 토큰/개인키 권한은 600이다. 모델은 기존 Azrael Qwen bearer-file 연결을 쓴다. 단말과 호스트가 연결되고 호스트·모델 서버가 실행 중이어야 한다. 현재 페어링 주소는 호스트 Wi-Fi 주소를 사용하므로 네트워크 주소가 바뀌면 재연결해야 한다. 자체 서명 인증서는 30일이며 만료/갱신 시 지문을 다시 페어링한다.

검사: `python3 opencli-nubi/test-chat-jobs.py`, `python3 opencli-nubi/test-user-directed-agent.py`, `python3 opencli-nubi/test-goal-mcp.py`. 실제 기기 시나리오는 별도 opt-in `GoalChatScenario`에서 네이티브 입력창을 채우고 전송 버튼을 누른다. 모델/도구를 가짜 응답으로 바꾸지 않는다. 모의 작업 검사와 실기기 실행 결과를 구분한다.
