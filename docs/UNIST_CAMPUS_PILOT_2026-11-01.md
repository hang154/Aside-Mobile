# 누비 UNIST 에타 시범: 학사 공지와 메일

목표: 학생이 학교 포털과 메일을 각각 뒤지지 않고, 자신에게 해당할 수 있는 공지를 출처·확인 시각·마감과 함께 보고 필요한 초안까지 이어간다. 모집 글을 실제 신청 완료로 표시하지 않는다.

## 시나리오

1. 포털 학사·장학·전체 게시판에서 계절학기·학점교류, 기말, 복학, 몰입캠프, 박사 자격시험, 졸업논문, 수업정원, 장학, 축제 및 시설 이용 제한을 수집한다. 게시판별 새 글과 수정 여부를 확인하고 기한과 대상은 본문에서 검증한다.
2. 전년도 이맘때의 공고는 올해 공고가 나올 가능성을 살피는 참고 신호다. 올해 확정 일정으로 안내하지 않는다. 사용자가 제시한 11~12월 날짜와 장학금 공고는 별도 검증 전 참고 사례다.
3. 수업정원 변경은 과목과 신청 기간을 확인해 수강신청 화면으로 이동한다. 수강 확정은 사이트 결과로만 판단한다.
4. 학교 메일에서 강연·세미나, 전공 상담, 장학금, 지원사업, 인턴십을 식별한다. 해당 가능성·마감·원문과 연결하고, 필요한 항목이 비어 있으면 명시한 신청서 초안을 만든다.
5. 인턴십 공고 → 원문과 첨부서류 확인 → 사실 확인이 필요한 입력 표시 → 신청 문서 초안 → 수신처와 첨부를 확인할 수 있는 Outlook 임시저장. 메일은 사용자가 확인한다.
6. 교수님께 시험·병결·점수 정정 메일: 수업명, 날짜, 사유 및 요청사항을 입력받아 추측하지 않고 초안을 만든다.
7. 알림은 새 글 또는 변경, 마감 임박, 사용자의 관심 분야를 기준으로 중복을 줄인다. 사용자별 학적·관심사·동기화 상태에 따라 해당 여부를 표현하고 불확실하면 확인 필요로 표시한다.

## 2026-11-01 검증된 범위

- 태블릿의 기존 로그인 세션으로 포털 홈의 전체공지와 학사공지 탭을 열었다. 학사공지 미리보기에서 복학, 겨울 계절학기 학점교류, 몰입캠프 후보가 보였다.
- `opencli-nubi/campus-notices-mcp.py`의 `nubi_portal_visible_notices`는 현재 열린 포털 홈의 선택된 탭을 읽는다. 10건과 복학·학점교류 후보 분류를 실기기 CDP/MCP로 검증했다. 제목은 포털 홈에서 말줄임 처리된 상태이며 분류는 후보일 뿐이다. 게시일을 신청 마감으로 취급하지 않는다. 이 도구는 PC에서 실행되고 ADB 포워딩에 의존한다.
- 연결된 Outlook 도구로 찾은 COOP 모집 메일의 제목은 2026-10-30 12:00 마감을 표시한다. 마감된 사례임을 명시한 문서 초안을 만들고, 연결된 Outlook의 임시 보관함에 수신인 없는 테스트 메일과 초안 파일을 저장했다. 자동 연동 제품 기능 검증이 아니라 도구를 이용한 수동 연계 시험이다.
- 포털 메뉴에서 게시판을 새 창으로 여는 시도는 WebView에서 빈 화면이 되었다. 본문·첨부파일, 전체 학사·장학 게시판, 자동 주기 수집, 개인화, 모바일 알림, 신청서 자동 작성·메일 자동 임시저장의 앱 내 연결은 검증되지 않았다.

## 다음 구현 순서와 완료 조건

1. WebView의 팝업과 파일 처리 지원을 안전하게 보완하고 기존 로그인 세션을 보존하여 전체 게시판과 글 상세를 연다. 학사·장학·전체 게시판에서 목록과 본문·첨부 접근을 각각 실기기 검증한다.
2. 글 고유 ID·게시판·게시 및 수정 시각·원문·조회 시각을 보관하고 변경·중복 감지와 날짜 파싱을 구현한다. 마감이 모호하거나 전년도 자료면 별도로 표시한다.
3. 학생이 연결한 계정과 관심사에 따른 필터, Android의 주기 실행과 알림 및 세션 만료 표시를 구현한다. OS 제한 아래 실제 전달 가능성을 실기기에서 검증한다.
4. 학생이 연결한 Outlook의 위임 권한으로 메일을 조회하고, 해당 공고와 첨부의 실제 양식에 맞게 빠진 내용을 명시해 문서를 생성한다. 수신인·첨부가 포함된 임시저장과 재열기를 검증한다.
5. 수강 정원 변경 → 해당 과목 조회 → 신청 화면 이동, 상담 신청서와 교수님 메일 초안 등 각각 입력부터 결과까지 테스트한다.
6. 에타에는 실기기에서 실제 연결된 기능만 시연한다. 학교 계정·개인정보가 노출되지 않은 테스트 화면을 이용한다.

## 후속 구현·검증

- 게시판 홈의 공지 주소가 `uspace.unist.ac.kr`로 새 창을 연다는 것을 확인했다. 기존 로그인 WebView에서 해당 링크를 직접 열어 전체공지 상세 및 학사공지 상세를 확인했다.
- `campus-notices-mcp.py`에 홈 미리보기 선택, 현재 게시판 목록 조회, ID·제목을 확인한 게시글 선택, 열린 상세 본문과 첨부명 조회, 게시판 화면 스냅샷 비교를 추가했다. 전체공지 목록 20행 → 창의설계축전 선택 → 본문 920자와 첨부명을 확인했다. 학사공지 목록 25행과 복학 공지 본문을 조회했다. 제목의 신청 기간은 2026-11-09 09:00~11-13 18:00이다.
- `campus_notice_store.py`는 현재 목록의 고유 ID와 제목·게시일·첨부 여부를 로컬 SQLite에 저장하고 새 글·변경을 구분한다. 빈 조회 결과는 기존 기록을 보존한다. 신규·중복·변경·빈 결과 회귀 시험과 실기기 학사 목록 2회 비교를 통과했다. 고정 글 중복 때문에 25행은 21개 고유 글이었다. 본문·첨부 내용 변경은 감지하지 않는다.
- Android 브라우저에 사용자가 연 새 창을 별도 WebView로 처리하는 코드를 추가하고 debug APK 빌드를 완료했다. 별도 패키지 시험 앱에서 `_blank`와 사용자 클릭의 `window.open` 팝업 열기·닫기를 검증했다. 기존 로그인 앱은 수정하지 않았다. 별도 시험 앱에서는 WebView 디버깅과 Activity 외부 실행을 시험용으로만 켰고 시험 후 앱을 삭제했다. 마지막에 창 정리 처리를 추가한 최종 코드는 빌드만 재검증했다.
- 현재 MCP는 PC의 ADB 포워딩으로 연결된 현재 WebView에서 동작하며, 자동 폴링·앱 내 통합·푸시 알림이 아니다. 장학게시판, 포털 실제 팝업의 수정본 사용, 수강신청 연결, 메일 자동 분류 및 신청 문서·임시저장의 앱 내 연결은 아직 미완료다. 에타 홍보에서 이 기능들을 완성된 기능으로 표현하지 않는다.

## 2026-11-01 추가 실기기 확인

- 기존 로그인 앱에서 학사 → 수강 → 개설강좌 조회를 열어 2026학년도 2학기 산업공학 전공 결과를 조회했다. `opencli-nubi/campus-courses-mcp.py`의 `nubi_course_visible_results`로 그 화면의 14행을 읽고 과목명으로 필터링했다. 조회 당시 데이터마이닝 IE20301은 정원 50명, 여석 3명이었다. 이 수치는 조회 당시 화면의 값이며 바뀔 수 있다. 이 도구는 이미 검색한 화면을 읽고 필터링하며 조회 조건 입력이나 수강 신청을 실행하지 않는다.
- 예비수강신청 화면에 표시된 2026년 2학기 접수 기간은 7월 20~24일이었으며 현재 접수 가능으로 확인되지 않았다. 수강 신청이나 확정은 실행하지 않았다.
- Android의 공지 작업 코드에서 같은 서비스 인스턴스의 직전 결과가 다음 실행에 섞이지 않게 초기화하고, 동시 작업으로 상태가 덮어써지는 것을 방지했다. 실계정으로 주기 수집과 알림을 받는 검증은 여전히 필요하다.
- 기존 로그인 패키지의 서명과 현재 로컬 빌드 서명이 달라 기존 앱에 덮어 설치할 수 없었다. 앱 삭제는 로그인 세션을 잃을 수 있어 수행하지 않았다. 새 창 수정본의 기존 세션 검증, 장학게시판 전체, Outlook의 앱 내 연결 및 실제 알림은 완료로 간주하지 않는다.

## 2026-11-01 기존 웹 세션으로 이어서 검증

- SAP 포털의 게시판 새 창은 내비게이션 대상 정보를 이용해 기존 창에서 열었다. U-Space 게시판 트리에서 학생게시판 → 학생공지 → 장학공지에 직접 들어갔으며, 실제 게시판 ID는 `1126`이다. 별도 앱 설치는 필요하지 않았다. 이는 새 창 수정본의 검증은 아니다.
- 장학공지 목록과 2페이지를 실기기 웹 세션 및 `nubi_portal_board_page` MCP로 읽고, 8332번 두산연강재단 공지의 본문과 첨부 3개 이름을 확인했다. 접수는 2026-10-14 09:00~11-13 18:00(KST), 2027년 1학기 2학년 진학 예정 등 자격 조건이 명시되어 있다. `nubi_doosan_2027_relevance`는 제공된 사실만 평가하고 미입력과 4.3 만점 평점의 환산은 확인 필요로 표시한다. 실제 사용자에 대한 최종 자격은 미확인이다.
- `campus-web-watch.py`는 기존 로그인된 U-Space WebView의 동일 출처 요청으로 학사 25행·장학 15행·전체 20행의 첫 페이지를 읽는다. 컴퓨터의 임시 사용자 systemd 서비스 `nubi-campus-web-watch.service`가 15분마다 확인한다. 실제 태블릿에서 모의 신규 공지를 이용해 비교 → 알림 등록을 검증했다. 첫 수집을 기준으로 삼으며 알림 실패 시 기록을 롤백해 재시도한다.
- 이 주기 수집은 PC가 실행되고 USB/ADB 연결, CDP 포워딩 및 U-Space 로그인 세션이 유지되어야 한다. 현재 첫 페이지만 감시하고 제목·게시일·첨부 표시만 비교한다. 앱 독립 실행·부팅 후 재시작·본문 변경·기한 임박·장학 자격 전체 판단은 아직 지원하지 않는다. 학사/장학 페이지를 전부 수집했다는 뜻이 아니다.
- 기존 누비 WebView에서 Outlook을 열자 Microsoft 로그아웃 화면으로 이동했다. 연결된 Outlook 도구에서는 이전 테스트용 COOP 첨부 임시메일을 다시 찾았다. 웹 내 메일 분류 → 문서 → 임시저장의 자동화는 실계정으로 아직 검증되지 않았다.

## 후속 SSO 및 Qwen 검증

- 포털의 실제 `e메일` 경로를 통해 학교 SSO를 거쳐 기존 누비 브라우저의 Outlook 받은편지함에 진입했다. Outlook 웹의 임시보관함에서 기존 COOP 테스트 메일을 직접 열고 DOCX 첨부를 확인했다. 이 초안은 앞서 연결된 도구로 생성한 것이며, 누비가 메일을 자동 분류해 새 초안을 만들었다는 검증은 아니다. 공고는 마감된 테스트 사례다.
- `qwen-campus-agent.py`는 Azrael에 설정된 Qwen 연결과 읽기 전용 공지 MCP를 연결한다. 실제 모델 `Qwen3.8-27B-abliterated-AWQ-W4A16`이 장학 목록 → 게시글 선택 → 본문 읽기 → 자격 판단을 호출했고, 접수 마감과 자격 확인사항을 올바르게 정리한 실행을 확인했다.
- 첫 모델 실행은 본문을 읽지 못했고 요일을 잘못 덧붙였다. 게시글 본문 프레임이 학교 보안 출처를 상속하는 `about:blank`인 경우 판독하도록 수정했고, 모델에 추정 요일과 사용자 신상 추정을 금지하는 지시를 추가했다. 이후 전체 도구 호출이 성공했으나 모델 출력의 정확성은 계속 원문 대조가 필요하다. 길이 제한으로 끊긴 답변은 성공으로 처리하지 않는다.
- Qwen 연결은 현재 공지 목록·페이지·본문·정해진 장학 자격 확인 도구만 지원한다. Outlook 메일 분류와 문서 생성·첨부 임시저장, 수강신청 연결, 주기 감시 운영 전체를 Qwen에 이관한 상태는 아니다. 위의 PC/USB·첫 페이지 제한도 그대로다.

## Qwen 단일 요청 실기기 연결 시험

- `qwen-campus-agent.py`에 화면 이동, 세 게시판 조회, 예비수강신청 화면 열기, 개설강좌 재검색 및 결과, Outlook 웹 검색·메일 본문 읽기, 로컬 DOCX 초안, Outlook 웹 첨부 임시저장, 공지 감시 상태·즉시 확인을 연결했다. Graph 도구는 별도 인증 설정이 없으면 사용할 수 없으며 웹 세션 경로가 별도로 존재한다.
- 2026-11-01 단일 요청에서 Qwen은 Outlook을 열고 COOP 모집 메일 검색 → 정확한 메일 본문·표시된 첨부 목록 조회 → DOCX 생성 → 수신인 없는 Outlook 초안에 첨부 → 웹 검색으로 저장 확인 → 장학게시판 복귀 → 세 게시판 감시 확인 → 최종 응답을 반환했다. 실계정 임시보관함에서 `[누비 E2E 1412] COOP 테스트 초안`과 첨부를 별도 확인했다. 해당 모집은 마감된 테스트 사례이며 발송하지 않았다.
- 1412의 DOCX는 지원자·지원 동기·경험이 `[직접 확인하여 입력]`으로 남았음을 파일을 열어 확인했다. 모델이 사용자에게서 받지 않은 개인 사항을 채우지 못하도록 실행 계층에서 제거한다. 실제 모집의 원본 HWP 양식에 맞춰 작성한 신청서는 아니다.
- 별도 단일 요청에서 Qwen은 포털 예비수강신청 화면을 열고 접수 기간이 아니라는 화면 메시지를 확인한 뒤 장학게시판으로 복귀했다. 실제 신청은 하지 않았다. 과목 선택 → 실제 수강신청 완료와 모든 학사·장학 조건의 개인별 판단은 미검증이다.
- Qwen은 한 응답에서 첨부 항목 4개를 나열하면서 5건이라고 적었다. 첨부 개수 추정을 금지하도록 지시를 보강했으나 모델 출력은 여전히 원문 대조가 필요하다. 오류·중단 시 초안 중복 생성 방지, 화면 로딩 대기, 누락 내용 표시가 구현되어 있다.
- 여러 번의 검증으로 Outlook 임시보관함에 `[누비 E2E ...]` 시험 초안이 남았다. 1408은 첨부 없는 미완성 시험이며, 1412가 위 단일 요청의 검증본이다. 메일을 발송하거나 기존 사용자의 초안을 지우지 않았다.
- 현재 실행은 로컬 PC의 명령줄에서 사용자 문장을 Qwen에 전달하는 형태다. 누비 앱 채팅 화면이나 Azrael의 일반 대화가 이 스크립트를 자동으로 호출하는 제품 통합은 아직 검증되지 않았다. PC/USB·로그인·첫 페이지 감시 제한은 그대로다.

## MCP 진입점 단일 요청 시험

- 기존 `mcp-server.mjs`에 `nubi_qwen_campus_task` 진입점을 추가했다. 이 MCP 도구에 사용자 문장 하나를 넣으면 Azrael의 Qwen 연결로 전달하고, Qwen이 필요한 캠퍼스 도구를 선택해 호출한 뒤 결과와 오류 상태를 반환한다. 실제 MCP JSON-RPC 호출로 2026-11-01에 실기기·실계정에서 검증했다.
- Qwen이 Outlook 웹 이동 → 메일 검색 → 원문 및 표시된 첨부명 확인 → 문서 생성 → 첨부 임시저장 → 장학게시판 복귀 → 공지 즉시 확인을 수행하고 최종 응답했다. `[누비 E2E 1413] COOP 테스트 초안`이 Outlook 임시보관함에 첨부와 함께 존재함을 별도 조회했다. DOCX에서 지원자·지원 동기·경험이 확인용 빈칸임을 별도로 읽어 확인했다. 수신인 없이 임시저장했고 발송하지 않았다.
- 예비수강신청 화면 열기 및 기간 판독도 Qwen 단일 요청으로 별도 실기기 확인했다. 실제 신청, 다른 개인의 전체 자격 판단, 전체 과거 게시판, 백그라운드 독립 운영, 학교 원본 HWP 양식 자동 작성은 완료된 기능이 아니다.
- MCP 서버 진입점은 로컬에서 직접 실행해 검증했으며 현재 Azrael 세션의 도구 목록에 동적으로 등록된 상태나 누비 앱 채팅에 연결된 상태는 아니다. `qwen-campus-agent.py` 실행과 이 MCP 호출은 PC·태블릿 CDP 연결에 의존한다. 현재 알림은 PC의 주기 서비스와 ADB를 이용한다.

## 누비 채팅과 Qwen 경로 시험

- 기존 목표별 누비 채팅의 HTTPS 중계에서 UNIST 관련 사용자 지시를 `qwen-campus-chat.py`와 `qwen-campus-agent.py`로 전달하도록 연결했다. 기존 앱의 사용자 입력 → Qwen → 태블릿의 로그인된 학교 WebView → 응답 경로다. 해당 연결은 PC의 중계 서비스, USB/ADB 포워딩 및 유지된 로그인 세션에 의존한다.
- 실기기 누비 채팅에서 한국어 요청을 입력·전송하여 Qwen이 예비수강신청 화면의 표시 기간을 읽고 장학게시판으로 돌아가는 결과를 받았다. 기존 instrumentation은 캠퍼스 답변이 목표 요약에도 저장되어야 한다고 검사해 실패했으나, 채팅 작업 상태는 완료였고 실제 Qwen 실행 기록에서 두 화면 이동과 응답을 확인했다. 신청은 진행하지 않았다.
- 학교 WebView 앱이 백그라운드에 있을 때 Android의 네트워크 제한으로 페이지 접근이 실패해 해당 앱에 기기 절전 예외를 적용했다. 열린 WebView를 유지한다는 보장은 없으며, 앱 또는 세션 종료 시 복구가 필요할 수 있다.
- 사용자 요청을 PC에서 실제 채팅 중계 API로 전달한 별도 시험에서 Outlook COOP 본문 → DOCX 테스트 초안 → 첨부된 수신인 없는 임시메일 → 장학게시판 복귀 → 감시 확인을 수행했다. 실제 학교 HWP 양식에 맞춘 신청서나 자동 발송을 뜻하지 않는다. 시험 초안이 Outlook에 남아 있다.
- 앱 화면에는 기존 공개 탐색 안내가 남아 있어 실계정 캠퍼스 작업을 설명하지 않는다. 일반 사용자 배포 전에는 실제 데이터 처리와 화면 안내, 독립 실행, 세션 복구 및 오류 처리의 검증이 필요하다.
- 앱 채팅을 통한 메일 복합 요청 재시험은 실패했다. Outlook을 백그라운드 웹뷰에서 검색하면 기존 결과 표시 후 검색 재실행 시 결과 영역이 비는 현상을 확인했다. Qwen이 검색을 반복하며 요청을 마치지 못했고, UI는 실패로 표시했다. 백그라운드 Outlook 선택과 `임시메일` 표현 처리는 보완했으나 전체 앱 채팅 메일 흐름은 미완료다. 중계 API 직접 호출 성공을 앱 UI E2E 성공으로 간주하지 않는다.
- 실패 시험 후 장학게시판으로 화면을 복원하고 3개 게시판 즉시 확인을 실행했다. 총 60행, 변경 0건으로 확인됐으며 이번 실행에서 새로운 알림 전달은 발생하지 않았다.

## 앱 채팅 → Qwen → 학교 메일 실제 시험 보완

- 앱 화면이 가려질 때 학교 작업을 취소하던 채팅 동작을 보완하고 같은 서명으로 태블릿의 목표 채팅 앱을 업데이트했다. 요청 중 기존 로그인 학교 브라우저 작업을 전면으로 가져오고, 종료 후 채팅을 다시 표시하는 PC 중계 프로토타입이다. 앱이 강제 종료되거나 기기가 재시작될 때의 복구는 검증하지 않았다.
- 태블릿 채팅에 직접 입력한 하나의 요청에서 Qwen은 Outlook의 COOP 검색과 본문 읽기, 테스트 DOCX 작성, 수신인 없는 Outlook 첨부 초안 임시저장, 장학게시판 복귀와 감시 상태 확인을 수행했다. 임시보관함에서 `[초안] 2027학년도 1학기 COOP 인턴십 신청서 - 미발송 임시저장`을 다시 열어 본문과 `nubi-campus-application-a8886113da3147b5a816e0bcdc3ff966.docx` 첨부를 확인했다. 전송하지 않았다. 공고는 이미 마감된 시험 사례이며 원본 HWP 신청 양식에 작성한 것은 아니다.
- 최초에는 Qwen이 문서 생성·저장을 생략하고 완료라고 답해, 요청에 필요한 도구의 성공 여부를 확인하고 누락 단계를 재요청하도록 보완했다. 임시저장 시도 전 Outlook으로 이동하고 재시도 중복을 막는다. 답변에 관측한 메일 제목·문서명·초안 제목을 붙이는 보완은 코드 컴파일을 확인했으며 이 변경 후 전체 메일 시나리오의 재실행은 하지 않았다.
- Android 계측 테스트의 기존 목표 요약 일치 검사는 캠퍼스 채팅에 적용되지 않아 실패로 표시됐으므로 캠퍼스 응답 존재와 완료 상태를 검사하도록 수정했다. 예비수강신청 기간 확인 → 장학게시판 복귀는 수정된 실기기 계측 테스트 PASS를 확인했다. 화면의 `학사력 기간이 아닙니다` 문구를 모델이 추가 해석한 사례가 있어 문구 그대로 전달하도록 지시했다.
- 브라우저 포그라운드 전환 중 앱 강제 종료와 사용자 수동 화면 전환, 연결 상실 후 재개는 검증하지 않았다. 기존 채팅 화면의 공개 탐색 전용 안내는 학교 실계정 연결 기능을 반영하지 못한다. 기기·세션과 PC·USB/ADB에 의존하며 전체 기능 완성이나 배포 준비 완료를 뜻하지 않는다.
- 결과 표시와 완료 판정을 보완한 최종 코드로 위 메일 복합 요청을 누비 앱에서 다시 실행했고 Android 계측 테스트가 PASS했다. Qwen 도구 기록에는 메일 검색·본문, 문서 생성, Outlook 초안 첨부 저장, 장학게시판 복귀, 감시 상태 확인이 각각 성공으로 기록됐다. 화면 답변에는 `nubi-campus-application-b9aa2e7451cb420286d09089d7ae7082.docx`와 임시저장 제목이 표시됐다. 이번 테스트도 발송하지 않았고 추가 테스트 초안을 남겼다. 초안 목록에서 별도 재열기 검증을 한 것은 앞선 `a8886113...` 첨부 사례다.
- 감시와 학교 브라우저를 위한 PC 서비스 및 USB 디버깅 의존은 그대로다. 에이전트가 모든 게시판 페이지, 모든 메일 시나리오, 개인정보에 근거한 자격 판단을 완수한다는 뜻은 아니며 원본 학교 HWP 양식, 앱 독립 지속 동작 및 전체 요청의 신뢰성은 추가 구현과 검증이 필요하다.

## 요청 대조와 장학게시판 제목 검색 확장

- `nubi_campus_board_search`는 현재 열린 학사·장학·전체 게시판의 학교 서버 측 제목 검색을 사용한다. 장학게시판에서 `두산`으로 2027·2026·2025년도 공고 3건, 일치 없는 검색 0건, `장학` 검색 1·2페이지의 서로 다른 비고정 공지를 실계정으로 확인했다. 검색 결과는 한 페이지씩 반환하며 100페이지를 넘는 조회는 지원하지 않는다.
- `nubi_campus_board_search_open`은 검색 첫 페이지에서 ID와 제목을 대조해 선택하고 본문 도구로 연결한다. 실제 2025년도 장학 공고를 검색·선택·본문 열람했고, 같은 흐름을 누비 채팅 → Qwen으로 재시험해 PASS했다. 첫 페이지를 벗어난 검색 결과의 선택 열기는 미구현이다.
- 일시적인 읽기 실패 후 동일한 도구 또는 검증된 대체 열기 도구가 성공한 경우 미해결 오류 목록을 갱신한다. 임시저장 도구의 실패는 중복 생성 가능성 때문에 자동 복구로 처리하지 않는다. 2025년 공고 요청에 2027년 전용 자격 판정 도구를 적용하지 않도록 했다.
- 채팅 앱의 공개 탐색 전용 안내를 학교 계정과 메일 초안 작업에 맞게 수정하고 빌드·설치 후 장학 제목 검색의 누비 채팅 실기기 계측을 다시 통과했다. 설치 APK SHA-256: `53c62cb92194873878bba2ff3b2558038b73d1cb47217c75e6a5a44c0b33f43f`. 공지 감시 즉시 확인은 3개 게시판 첫 페이지 60행·변경 0건이며 새로운 알림 전달은 없었다.
- 로컬에 보관한 이번 캡처는 테스트 직후 누비 홈 화면이며 검색 결과 화면 캡처는 아니다. 전체 요청 대조와 미완료 범위는 `NUBI_REQUEST_COMPLETION_AUDIT.md`를 참조한다.
- 이후 검색 2페이지의 고정글이 아닌 장학 공지 2건을 ID·제목으로 선택해 해당 상세 화면으로 이동했다. 두 공지는 이미지로만 된 본문이었다. 본문 도구는 이미지 수와 텍스트 부재를 반환하며 이미지 내용을 읽었다고 주장하지 않는다. Qwen은 이미지 전용 본문을 읽기 완료로 처리하지 않는다. 검색 3페이지 이후의 선택과 이미지 내용 해석은 검증하지 않았다.
- 이미지 전용 본문 요청을 누비 채팅에서 시험했을 때 Qwen은 실제 내용을 읽었다고 완료 처리하지 않았고, 수정 후 채팅에 `본문이 이미지로만 표시되어 텍스트 내용을 확인하지 못했습니다. 원문 이미지를 직접 확인해야 합니다.`라고 표시했다. 해당 실패는 의도된 미완료 판정이다. 시험 후 장학게시판을 복원해 세 게시판 첫 페이지 60행을 다시 확인했다.
