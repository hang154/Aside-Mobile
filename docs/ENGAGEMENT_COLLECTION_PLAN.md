# 화면 맥락·반응 수집 계획

## 목표와 경계

사용자가 선택한 화면에서 사용자가 명시적으로 요청한 도움을 제공하기 위한 정보만 사용한다. WebView와 외부 앱 화면은 별도 동의와 별도 수집 스위치로 구분한다. 사용자가 일시 정지·종료·기록 삭제를 할 수 있도록 설계한다. 아래는 계획이며, 이번 작업에서 상시 수집 기능이나 외부 전송을 구현한 것은 아니다.

| 항목 | 앱 내 WebView | 다른 앱의 사용자 승인 화면 | 주의 |
|---|---|---|---|
| 현재 화면 | 페이지 로드·탭·포그라운드 상태와 출처 도메인 | 접근성 창 전환 이벤트와 허용된 앱의 패키지 | 도메인·앱명도 개인 정보일 수 있다. URL 경로·쿼리는 기본 저장하지 않는다. |
| 선택·조작 | 앱이 제공한 버튼 및 허용된 웹 요소의 클릭 이벤트 | 선택된 앱에서 지원되는 접근성 클릭·스크롤·창 전환 이벤트 | Android 이벤트는 앱과 뷰에 따라 누락된다. 터치나 버튼 의미를 항상 알 수 없다. |
| 체류 | 화면 표시·포커스·잠금·백그라운드 전환 시 단조 시계로 구간 계산 | 허용된 앱의 창 활성 및 전환 시 단조 시계로 구간 계산 | 화면 표시 시간이지 시선·주의·관심의 증거가 아니다. 팝업·다중 창·잠금·절전 상태를 별도 처리한다. |
| 내용·화면 | 사용자가 특정 게시물이나 페이지를 공유·선택한 경우에만 별도 처리 | 사용자가 특정 화면을 공유·요청한 경우에만 범위 제한해 처리 | 비밀번호·OTP·금융·메시지·인증 등은 수집하지 않는다. 민감 화면 차단은 완벽하다고 보장할 수 없어 기본 수집 대상에서 제외한다. |
| 반응·의도 | 사용자의 좋아요·저장·직접 메모 등 명시적 동작과 직접 선택한 요청 | 사용자가 입력한 명시적 요청·동의한 동작 | 클릭이나 머무름만으로 욕구·감정·구매 의도를 사실처럼 추론하지 않는다. 제안은 추정임을 표시하고 사용자가 교정한다. |

## 구현 방향

1. 시작 전 수집 항목·목적·저장 위치·보존 기간을 별도 화면에 설명하고 사용자 동의를 받는다. 대상 사이트·앱, 내용 수집 여부, 수집 중지와 삭제를 사용자가 제어한다.
2. WebView는 자체 Activity 수명주기, 화면 잠금, WebView 탐색과 앱 버튼 이벤트를 우선 사용한다. DOM 관찰이 필요하면 선택된 페이지에서 제한된 일회성 스냅샷을 검증해 처리한다. 웹페이지에 네이티브 브리지를 무차별 노출하지 않는다. 페이지·광고·iframe은 신뢰하지 않는다.
3. 다른 앱은 허용된 앱에 한정해 사용자 요청에 반응하는 접근성 이벤트를 검토한다. 민감 입력·보호 화면·대화·금융 앱을 기본 제외하고, 내용 저장이나 제3자 전송은 별도로 동의받기 전까지 하지 않는다. Play 배포 시 접근성 API의 별도 고지·동의와 제한을 검토한다. [Google Play 접근성 정책](https://support.google.com/googleplay/android-developer/answer/16558241), [Android 접근성 이벤트](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent.html).
4. 이벤트에는 무작위 세션 ID, 출처 유형, 허용된 이벤트 분류, 단조 시각, 동의 버전만 필요한 범위에서 기록한다. 원문·검색어·URL 쿼리·자격 증명은 수집하지 않는다. 보존 기간과 로컬 삭제를 제품에서 설정하고 전송이 있다면 목적별로 따로 동의받는다.
5. 포그라운드·잠금·화면 전환, 중단·재개, 민감 정보 차단, 사용자 데이터 삭제, 다중 창, 제어 실패와 오탐을 실기기에서 검사한다. 사용자가 수행한 행동, 에이전트가 수행한 테스트 행동, 추정은 별도 기록한다.

## 이번 실험의 범위

태블릿에서 ADB와 UI Automator로 사용자가 허용한 테스트 화면을 열고, 앱 내 WebView와 Android 설정 앱의 접근성 계층을 각각 일회성으로 샘플링한다. 스크립트는 정해진 패키지의 요소 수와 테스트 단계·시각만 로컬 JSON에 저장하며 UI 계층 원문과 입력값은 저장하지 않는다. 웹페이지 로드와 일정 시간 대기, 관찰·선택 화면을 테스트하고 다른 앱 화면 샘플도 확인한다.

이 실험은 시스템 테스트 도구를 통한 **제어된 단발성 표본**이다. Aside 앱에 실사용자 동의·상시 이벤트 수집·정확한 체류시간 측정·반응 분석을 구축하거나, 실제 사용자 선택·감정·의도를 검증한 것은 아니다. 화면 녹화 파일은 별도 로컬 폴더에만 보관한다.

## 제어된 태블릿 시험 결과 — 2026-10-30

- 별도 설치된 Aside 브라우저에서 `example.com`을 열고, 관찰 버튼 → 항목 선택 → 실행 확인 창 → 취소를 테스트했다. 관찰 결과·선택 대화창·확인 대화창의 존재가 각각 감지됐다. 이 선택은 테스트 담당자가 수행한 행동이다.
- WebView 화면의 계층에는 26개 노드와 클릭 가능 속성이 있는 노드 8개가 기록됐다. Android 설정 화면의 두 표본에는 각각 123개 노드와 클릭 가능 속성이 있는 노드 11개가 기록됐다. 이는 계층 개수이며 화면에 실제 노출된 요소나 사용자가 본 요소의 개수가 아니다.
- WebView 두 표본의 단조시계 간격은 약 7.16초, 설정 화면은 약 7.90초였다. 중간 상태를 연속 관측하지 않았고 각 UI 계층 수집에도 시간이 소요되므로 실제 체류시간으로 산정하지 않는다.
- ADB 테스트의 `events.json`과 스크립트·화면 영상은 사용자 기기와 연결된 컴퓨터의 로컬 폴더에만 저장했다. UI 트리 원문·텍스트·입력값은 결과 JSON에 남기지 않았다. 화면 영상은 화면에 보인 정보가 포함될 수 있다.
- 앱 내 실사용자 동의, 접근성 서비스 이벤트 구독, 연속 체류 측정, 반응·의도 수집 및 외부 전송은 구현·검증하지 않았다. 기기에서 실사용자 반응이나 의도라고 판정한 내용도 없다.
