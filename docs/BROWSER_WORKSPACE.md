# Aside 모바일 브라우저 작업 공간

## 목표

사용자가 소유한 Android 앱의 WebView에서 웹 페이지를 열고 사용자가 승인한 작업을 실행한다. 장기 목표는 인증된 중계 서버와 외부 에이전트의 제한된 도구 연결이다. 브라우저 안의 자동화는 Android 접근성 서비스와 별개다.

## 현재 0.6 구현 범위

- HTTPS 열기, 뒤로 가기, 스크롤, 사용자 직접 로그인 및 WebView 쿠키 유지.
- 현재 페이지의 링크·버튼 이름을 최대 30개 표시하고, 사용자가 항목과 실행을 각각 선택한 뒤 누른다. 페이지 주소나 항목 이름이 바뀌면 재관찰한다.
- 사용자가 직접 입력한 검색어를 `input[type=search]`에만 채운다. 비밀번호·OTP 입력 자동화와 제출은 제공하지 않는다.
- Android에 JavaScript 브리지를 노출하지 않고, 파일 및 content 접근과 혼합 콘텐츠를 제한한다. WebView 활동은 외부 앱에서 실행할 수 없다.
- 별도 앱 패키지의 WebView 저장 공간을 사용한다. 동일 앱 안에서 여러 세션으로 나누는 AndroidX Profile 기능은 구현하지 않았다.

## 아직 구현하지 않은 부분

원격 중계 서버, 기기 페어링, 에이전트 인증·권한·승인 프로토콜, MCP/WebSocket, 원격 관찰·클릭·입력, 사용자 승인 만료, 감사 로그, 취소·재연결, 백그라운드 작업은 없다. Dots·피클의 직접 연동과 Credential Manager, SMS 동의 API, 로그인 호환성, 결제 단계의 별도 승인, 탭 및 프로필 관리는 검증하거나 구현하지 않았다. 로컬 모델도 이 브라우저의 제어 도구에 연결되지 않았다.

웹페이지의 버튼은 실제 구매·전송 같은 행동을 수행할 수 있다. 표시되는 이름만으로 기능을 보증할 수 없으므로 사용자가 화면에서 확인한 항목만 실행한다. 로그인·인증 정보는 사용자가 직접 입력하며, 웹사이트가 WebView 로그인 또는 자동화를 지원하는지는 사이트별로 다르다. 페이지는 네트워크를 사용한다.

## 다음 구현 조건

서버와 인증 방식이 정해지면 사용자 기기에서 먼저 TLS 중계 서버로 연결하고, 사용자별 기기 페어링, 짧은 수명의 작업 권한, 명시적 승인과 종료, 응답 검증을 구현한다. 웹 콘텐츠는 신뢰하지 않으며 자격 증명과 민감 입력은 모델에 전달하지 않는다. Android가 프로세스를 중단하거나 화면이 닫힌 경우 작업이 지속된다고 가정하지 않는다.
